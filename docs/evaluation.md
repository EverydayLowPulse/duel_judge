# 評価の設計

Phase 1（MVP）で「どのモデルを採用するか」「出荷してよいか」を決めるための採点ルール。  
テストセットの作り方（Q&Aホールドアウト）は `project.md` 参照。ここはその**採点方法**。

## 評価セットの2種類

| セット | 作り方 | 測ること |
|--------|--------|----------|
| A. 直接Q&A | ミラーした公式Q&Aから問題を作る。正解Q&Aは検索対象に**含めてよい** | 検索＋引用＋結論が公式と一致するか（通常運用に近い） |
| B. ホールドアウト | 一部Q&Aを検索から除外し、ルール推論だけで答える | Q&Aが無い／見つからないときの推論力と、でっち上げないか |

MVPのモデル選定は **Aを主、Bを副** とする。Bは `confidence: low` や `withhold` の振る舞い確認にも使う。

規模: **合計20〜50問**（A: 15〜40、B: 5〜15 程度）。初回は人手採点。

## 1問あたりの記録項目

```json
{
  "id": "eval-001",
  "set": "A",
  "question": "（ユーザー質問文）",
  "gold": {
    "conclusion_summary": "結論の要約（人手で1〜2文）",
    "must_cite_urls": ["https://dm.takaratomy.co.jp/rule/qa/..."],
    "must_rule_refs": ["111.1"],
    "allowed_confidence": ["high", "medium"]
  },
  "notes": "採点時の注意（任意）"
}
```

- `must_cite_urls` / `must_rule_refs` は「最低これがあればよい」のリスト。余分な正しい引用は減点しない
- セットBでは `must_cite_urls` を空にし、ルール参照や `low` / `withhold` を期待してよい

## 採点軸（1問ごと）

人手で Yes/No。部分点は使わない（裁定AIでは曖昧な点が危険）。

| 軸 | 合格条件 | 落ちたら |
|----|----------|----------|
| **結論一致** | `conclusion` が gold の結論と矛盾しない（言い回しの差は可） | 不正解 |
| **出典ゲート** | Evidence Gateを通過している（引用あり・正規化後照合OK・公式URLのみ） | 不正解 |
| **必須出典** | gold の `must_cite_urls` / `must_rule_refs` を満たす（セットA） | 不正解 |
| **ハルシネーション** | 取得済みチャンクに無い裁定・架空URL・架空ルール番号を書いていない | **即不合格（1件でもアウト）** |
| **確信度** | `confidence` が状況と整合（直接Q&Aなのに `low` だけ、等は不可）。許容リストがあればその中 | 不正解 |
| **形式** | `answer` / `clarify` / `withhold` のいずれかでスキーマ違反なし | 不正解 |

### 「正答」の定義（MVP）

次をすべて満たせばその問は **正答**:

1. 結論一致
2. 出典ゲート通過
3. 必須出典を満たす（セットA）
4. ハルシネーションなし
5. 確信度が妥当
6. 形式OK

根拠のルール番号まで gold と完全一致は、MVPでは **必須出典に書いたものだけ** 見る。書いていない追加の正しい引用は減点しない。

## 集計指標

| 指標 | 定義 | Phase 1 の目安 |
|------|------|----------------|
| **正答率** | 正答数 / 全問 | セットAで **70%以上** を採用ラインの目安 |
| **ハルシネーション件数** | 上記軸でアウトになった件数 | **0件**（1件でもそのモデルは原則不採用） |
| **ゲート通過率** | Evidence Gateを通った回答数 / 回答を試みた数 | 参考指標（低いと引用設計が弱い） |
| **不当 withhold 率** | 答えられるはずなのに `withhold` した割合 | 参考（高すぎると使えない） |
| **レイテンシ・コスト** | 1問あたりの秒数・概算円 | 同性能なら安い方 |

裁定AIでは「たまに嘘をつくが正答率は高い」より「正答率が少し低くても捏造しない」を優先する（非対称な基準）。

## 誰が採点するか

| 段階 | 方法 |
|------|------|
| Phase 1 初回 | **人手**（あなた）。基準のブレを自分で見て直す |
| 問が増えたあと | 人手を正とし、必要なら LLM-as-judge を補助に（最終決定は人手） |

LLM-as-judge を最初から主審にしない。裁定の正誤はドメイン知識が要り、採点LLM自身がハルシネーションしうるため。

## モデル比較の手順

1. 同じ評価セットで候補モデルを回す
2. ハルシネーション件数 > 0 のモデルは候補から外す（または要再検証）
3. 残りで正答率・コスト・レイテンシを比較
4. デフォルトモデルを1つ決める

## 継続評価

- 本番（または自分用）で誤回答・不確実な回答をログし、評価セットに足す
- 新弾後はQ&Aが増えるので、セットAを定期的に入れ替える
- ホールドアウトに使ったQ&Aは、評価期間中は検索インデックスに戻さない
